# Browser and reading-surface assessment

Assessed for v0.5.0 on 2026-10-14. A packaged draft, webpage lab or passing DOM test does not establish native extension compatibility.

| Target | Concrete delivery | Remaining validation or owner step |
| --- | --- | --- |
| Chrome desktop | MV3 ZIP, activeTab-only activation, shortcuts, local preferences and drafts | Native installation/upgrade/runtime, developer account registration/payment, publisher declarations, review and store URL |
| Edge desktop | Same Chromium package; Edge can install an approved Chrome Web Store listing after allowing extensions from other stores | Native Edge test and an approved Chrome listing are pending. A separate Microsoft publisher account is needed only if choosing an additional Edge Add-ons listing |
| Firefox desktop | Separate `-firefox-preview.zip`, nonpersistent background scripts, `browser` promise API namespace, stable extension ID, minimum Firefox 140 and no automatic data collection declaration | Native runtime, clipboard behavior, permissions/shortcuts, AMO account/signing/review. Unsigned ZIP is a developer draft, not a one-click installer |
| Safari macOS/iOS | Conversion assessment and shared web engine/data; regular-browser workshop usable without installing an extension | Local Safari packager is unavailable (`xcrun --find safari-web-extension-packager`). App Store Connect or an appropriate Apple toolchain plus owner developer membership/signing and device testing are required |
| Mobile web | Responsive workshop, guide, document reader and demo, no account | Narrow desktop viewport checks are not real-device testing; OCR memory, keyboards and assistive technology still need device checks |
| Firefox Android | Feasibility only; not advertised in Firefox manifest | Mozilla's Android compatibility declaration, Android runtime and store review after desktop stabilization |

Firefox's background model differs from Chromium, so the build replaces `background.service_worker` with `background.scripts`. The code selects the promise-based browser namespace when available. No new host permission is introduced. See [Mozilla background documentation](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background) and [namespace differences](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Chrome_incompatibilities).

The Firefox draft declares a minimum of 140, matching the desktop introduction of built-in data-consent declarations. Ordinary reading, preferences and drafts stay local; the reviewer must also inspect the explicit user-directed GitHub feedback link. A final store declaration must describe the final shipped behavior. See [Mozilla data consent](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/) and [browser-specific manifest settings](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/browser_specific_settings).

Microsoft documents [installing Chrome Web Store extensions in Edge](https://support.microsoft.com/en-us/edge/add-turn-off-or-remove-extensions-in-microsoft-edge). That route does not require a separate Edge publisher account. An optional independent Edge Add-ons listing needs a publisher account and submission; see [Microsoft's extension overview](https://learn.microsoft.com/en-us/microsoft-edge/extensions/). Neither route establishes this extension's native Edge compatibility. Apple now documents both local packaging and App Store Connect packaging; owner account access and distribution obligations remain. See [Apple packaging](https://developer.apple.com/documentation/safariservices/packaging-a-web-extension-for-safari) and [distribution](https://developer.apple.com/documentation/safariservices/distributing-your-safari-web-extension).

## Additional reading surfaces

| Surface | Decision in this release | Reason and next experiment |
| --- | --- | --- |
| Plain paragraphs | Local workshop with original/reading comparison, single-occurrence undo, original copy and reset | Explicit phrases; a separate sentence experiment handles only conservative semicolon splits |
| Text PDFs | Local PDF.js parser, page canvas and selectable text layer, original item coordinates, editable extracted text and checked reading comparison | No built-in PDF viewer injection. Engine order can be wrong; the original stays visible and reading requires explicit checking. Limits: 15 MB, 100 pages, one page at a time, 20,000 extracted characters/items; encrypted PDFs unsupported |
| Scanned PDFs/images | Local English Tesseract OCR for PNG/JPEG and PDF scan pages, with higher-resolution OCR rendering separate from the screen preview | Check all words, numbers, units and negation before reading; engine confidence is not accuracy validation. 20-million-pixel cap; original files/text are not uploaded or persisted. Complex handwriting/layout and other languages are outside the experiment |
| Iframes | Explicit opt-in, off by default: accessible same-origin HTML documents in the currently activated tab | Each accessible frame document has its own observer, styles, events and restoration. Frame load/navigation retires the old document. Cross-origin, inaccessible, sandbox-isolated, non-HTML and not-yet-ready documents stay skipped. No frame fetch, sandbox modification or extra host permission |
| Shadow DOM | Explicit opt-in, off by default: open roots on eligible connected hosts | Separate scoped observers, styles and keyboard events preserve existing component DOM. Closed roots stay inaccessible. Nested accessible surfaces work only when their corresponding opt-ins are on; slots retain their light-DOM text without being scanned a second time |
| Inline HTML | Supported only across documented transparent inline tags; complex/interactive boundaries stop a phrase | The reader keeps existing elements and restores owned text; see the regression fixtures and release evidence |
| Full sentence rewriting | Separate deterministic semicolon-split proposals with exact differences, explicit review and undo; no generative paraphrase | Word/number sequence check is not proof of semantic equivalence. Quoted input and recognized conditional patterns stay original; independent review/comprehension validation remains open |

The compatibility lab exposes real same-origin `srcdoc` frames, open and closed components, navigation, removal, host edits, split phrases and page limits. Its two opt-ins start unchecked. The lab uses the webpage DOM reader; it does not install an extension or verify native injection, browser host-permission prompts, signing or store installation. Run `npm run preview:site` locally; the public [workshop](https://jakezwang.github.io/openplainenglish/demo/workbench.html) and [compatibility lab](https://jakezwang.github.io/openplainenglish/demo/compatibility.html) reflect their deployed release.

### Shared lifecycle and limits

All active surfaces share 750 logical phrase marks and a 15,000 nonempty-text-node limit per coordinated scan batch. Element traversal is also bounded. A phrase may span at most 24 text segments in a transparent flow run of at most 50,000 characters. Discovery admits at most 32 additional surfaces. Reaching a limit reports a partial-page state; an incomplete run is left untouched. These are coverage limits, not promises of whole-page interpretation.

Mode, interface language, density and highlight apply to every active scope. Restore-original, opt-out and reader destruction restore every retained private text segment that the host has not rewritten. One-occurrence restore remains local to that occurrence; page ignore is shared across current and later surfaces in the same reader session. Removing a host/frame or changing its document tears down its observers and handlers, without reinserting removed content or overwriting host text edits. Print handling uses original wording across active scopes. Frame/component content remains local and feedback still receives only the glossary entry and chosen feedback kind.

Newly inserted hosts, ordinary open-root DOM updates and frame `load` events are observed. Calling `attachShadow` on an already connected host emits no parent DOM mutation. The reader deliberately does not patch the site's `attachShadow` prototype or poll: use **Refresh surfaces**, re-enable reading, or a later discoverable DOM change to discover that root. Closed roots remain skipped. Hidden, editable, interactive, inert or non-English host regions are conservatively excluded.

`tests/surfaces.test.mjs` covers independent/default-off opt-ins, shared budgets, mode/preferences, local restore and shared ignore, dynamically added roots, frame-document replacement, removal/teardown, host edits, printing, exclusions, nested/direct shadow text and explicit late-root refresh. The frame-navigation fixture swaps actual DOM document contexts and dispatches a load event; it is a lifecycle unit test, not a claim that a native browser navigation or extension runtime was exercised.
